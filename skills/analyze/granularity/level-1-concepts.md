# Level 1: 概念字典

## 何时用
参考 METHODOLOGY.md §三 Q1。

**典型场景**:
- 速查表 (cheat sheet)
- API 概览页
- 用户问"这个文档讲什么"
- 入门了解

**Token 预算**: < 1k tokens 输出

## 核心提取内容
- 概念名 (canonical)
- 1-2 句定义
- 出现章节 (e.g. "§3.2" 或 "page 12")

**不提取**:
- 概念间关系
- 分类层级
- 原文证据

## 输出文件: `concepts.md`

```markdown
# <doc_name> 概念字典 (L1)

> 自动生成 by paper-reader analyze v2.0 | 档位: L1 | 日期: <date>

## 概念列表

### <概念名 1>
**定义**: <1-2 句>
**出现**: <章节定位, e.g. "§3.2" 或 "page 12">

### <概念名 2>
**定义**: <1-2 句>
**出现**: <章节定位>

...

## 元信息
- 文档: <doc_name>
- 页数: <page_count>
- 提取时间: <iso timestamp>
- 概念总数: <count>
```

## 示例

**输入** (用户指南片段):
> "AMBER 是一套分子动力学模拟程序。sander 是 AMBER 的核心 MD 引擎。pmemd 是 AMBER 的高性能 MD 引擎..."

**输出**:
```markdown
### AMBER
**定义**: 一套分子动力学模拟程序集。
**出现**: §1.1

### sander
**定义**: AMBER 的核心 MD 引擎，用于能量最小化和 MD 积分。
**出现**: §1.1

### pmemd
**定义**: AMBER 的高性能 MD 引擎，针对 GPU 优化。
**出现**: §1.2
```

## 反模式
- ❌ 写超过 2 句定义 → L1 只要字典
- ❌ 加关系 (X 包含 Y) → 升 L2
- ❌ 加分类 (X 是 Y 的子类) → 升 L3
- ❌ 概念漏掉关键章节 → 完整性差
- ❌ 概念总数 < 10 → 漏提取（除非文档本身就 < 5 页）

## 自检
- [ ] 每个概念都有 1-2 句定义（不能空）
- [ ] 概念数 ≥ 10（少于 10 是漏提取）
- [ ] 出现章节定位（不是模糊的"文中"）
- [ ] 没有 relations / hierarchy / evidence（L1 不要这些）
- [ ] 概念名 canonical（用文档原词，不擅自翻译）
